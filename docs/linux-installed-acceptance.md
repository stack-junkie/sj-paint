# Installed Linux acceptance

Use a disposable Linux x64 environment with an owned X11 display, one named desktop shell, Chrome, Node matching .nvmrc, locked build dependencies and Electron system libraries. The v0.3.0 acceptance used Ubuntu 24.04 and Xfce. It passed real installation, GIO launch with normal sandboxing, Graphics menu access, drawing, Save/reopen and owned shutdown. Final packaged background removal, object selection and erase also passed; see [PARITY.md](../PARITY.md) for evidence and limits. The recipe does not authorize unrelated host installation or configuration changes.

1. Record OS, desktop-shell version, display server, scale, candidate source manifest and archive SHA-256. Build/package the same finalized source as Windows and run the ordinary isolated browser/desktop checks.
2. Run `npm run archive:linux`, then `SJ_PAINT_DISPOSABLE_DISPLAY=1 xvfb-run -a python3 scripts/verify-installed-linux.py`. Keep `output/linux-installed-launch.json`, `output/linux-installed-workflow.json` and the archive checksum. Require no failures and confirmed owned process exit. This runs the real per-user installer under a temporary home, then GIO normal launch and a separate instrumented file workflow. Chooser responses in that workflow are supplied by the harness.
3. In the disposable user's graphical session, run the archive's `install-linux.sh` as that user. Open the application menu, locate Stack Junkie Paint and capture its name/icon/category presentation directly to a file. Launch from that entry without adding flags. Record whether one usable drawing window opens. This establishes the named shell/session, not every distribution or Wayland.
4. Draw a short stroke, add a text caption, Save As a new .sjpaint, close normally and reopen from the app. Confirm artwork/layers, clean saved state, and a new edit followed by Undo/Redo. Exercise chooser Cancel and Save-close Cancel with disposable work, confirming edits survive. Retain the saved bytes and action record.
5. Verify managed AI through the installed app using an explicitly preserved, task-owned profile. The installed runner accepts `SJ_PAINT_TEST_WORKFLOW=managed-status`, `managed-ai` or `managed-generation`, `SJ_PAINT_TEST_MANAGED_PROFILE` as the absolute profile directory, and `SJ_PAINT_TEST_PHOTO` as an absolute original photo fixture for removal/selection inference. It removes developer runtime/model environment overrides and verifies the activation receipt survives. The status mode does not run inference; the AI mode exercises real background-removal and object-selection workflows. Generation additionally requires an explicit absolute `SJ_PAINT_TEST_CAPACITY_SAMPLER` module exporting `sampleCapacity`, `closeCapacity` and `pendingCapacityOwners`, and a fresh absolute `SJ_PAINT_TEST_GENERATION_OUTPUT` directory. The sampler must report host commit headroom, not guest free memory; GPU sampling is optional for CPU erase. Its cleanup must confirm actual reader-process closure; a deadline failure retains ownership and is recorded before waiting for late closure. This mode exercises real candidates, selected edits, Save/Apply/Undo and Copy in the owned display. Retain model/runtime identities, output images, quality review, resource observations and confirmed release. Setup success alone is insufficient.
   For `managed-ai`, also set `SJ_PAINT_TEST_AI_OUTPUT` to a fresh absolute evidence directory. The fixed photo-selection prompts require the retained NASA astronaut PNG with SHA-256 `88431cd9653ccd539741b555fb0a46b61558b301d4110412b5bc28b5e3ea6cb5`; the helper rejects a different fixture. It retains all three actual decoder masks and preview screenshots, then verifies alternative selection, exact deletion and Undo. Keep the fixture outside Git.
   For `managed-generation`, set `SJ_PAINT_TEST_PHOTO` to the retained 1024-pixel NASA edit derivative with SHA-256 `c85038b3d12b345c37c4ec681473c00e762e526c4b263c62747457c67d68cded`. This is a different fixture from the removal/selection original. The finite journey covers one early erase cancellation and one completed photo erase request. It uses the actual submitted mask to verify unchanged outside pixels and compares saved candidates and applied drawing pixels with their previews, including Undo/Redo. Review retained images for useful quality; mechanical success alone does not establish it. The Windows counterpart takes this fixture through `--workflow managed-generation --photo-fixture <absolute path>` and deliberately skips the host clipboard.
6. Close only the owned application and dispose of the test environment according to its owner's lifecycle after retaining evidence. Do not terminate unrelated processes. A failed cleanup remains an explicit failure with ownership evidence.

This recipe verifies the supported Linux product. Retained native Microsoft Paint observations are separate evidence, and further parity research is not required for this release. All work stays in the owned background display. Reuse retained bounded Print/PDF evidence; physical-printer certification is excluded. Retained AI integration and useful output are part of release acceptance.
